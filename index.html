What It Does

A simple yet effective remediation loop for development and staging clusters.

Watches Pods

Monitors all pods in a specified Kubernetes namespace, keeping a constant eye on container states.

Detects CrashLoopBackOff

Identifies containers stuck in CrashLoopBackOff state and flags them for remediation.

Deletes Failed Pods

Removes the problematic pod so its controller can spin up a fresh, healthy replacement automatically.

Kubernetes Recreates

The pod's Deployment, ReplicaSet, or StatefulSet controller automatically recreates the pod after deletion.

What It Doesn't Do Yet

Retry budgets Cooldown windows Policy-based remediation Slack / webhook output Metrics & monitoring Helm chart packaging

🚀 Quick Start

Get KubeRescue running in under two minutes.

1

Create & Activate Virtual Environment

python -m venv .venv
source .venv/bin/activate
pip install -e ".[dev]"
2

Run Unit Tests

pytest -v
3

Run KubeRescue

kuberescue --namespace default

Tries in-cluster config first, falls back to local kubeconfig.

🧪 Docker Desktop K8s Demo

A safe, isolated demo that creates an intentional CrashLoopBackOff to showcase KubeRescue in action.

!

Prerequisites

  • Docker Desktop running with Kubernetes enabled
  • kubectl config current-context returns docker-desktop
  • kuberescue:local image exists from Docker build

Run the Demo

# Create test namespace
kubectl create namespace kuberescue-test

# Deploy crashing workload
kubectl apply -n kuberescue-test -f examples/crashloop-demo.yaml

# Run KubeRescue
kuberescue --namespace kuberescue-test

# Watch pods get replaced (in another terminal)
kubectl get pods -n kuberescue-test

# Clean up
kubectl delete namespace kuberescue-test
